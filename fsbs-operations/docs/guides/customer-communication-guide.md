# Customer Communication Guide

## The rule for every message
What happened → what the customer needs to know → whether they need to act → one link (to the specific relevant portal section) → one phone number. See `communications/customer-messages.md` for the full library and the 9 writing rules at the end of that document.

## Specific do's and don'ts
- Always name Five Star Bath Solutions of Ottawa immediately — never send an ambiguous "your appointment is confirmed" without the business name in the first line, especially for SMS.
- Never describe a tentative or reserved installation date using confirming language. If it isn't locked in, say so.
- Every payment-related message names the exact project, address, and amount, and always routes through the portal — never a bare external payment link. This is a deliberate anti-phishing safeguard (added after independent review) given this customer base is a known target for e-Transfer-style scams.
- Respect the 24-hour communication cooldown for non-urgent messages (`06-future-state-operating-model.md` §12) — don't manually send an extra reminder on top of an automated one without checking whether one already went out.
- Record consent before sending marketing-type messages; a service-related transactional message (appointment reminder, contract delivery) doesn't require separate marketing consent, but a satisfaction survey or review request should respect the same cadence/consent expectations.
- Check the customer's recorded language preference before sending — don't assume English by default now that the field exists (see `03-requirements-register.md` item B11).

## Escalation language
Never let an automated message imply a warranty determination, a discount, or a liability decision has been made. If in doubt, route to a human before sending.
